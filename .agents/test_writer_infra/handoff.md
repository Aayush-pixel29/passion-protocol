## 2. Logic Chain
1. **Assertion Engine**: Designed `test_framework.ts` to be dependency-free and runtime-agnostic under `tsx`, using `performance.now()` for millisecond timing, recursive object inspection for deep equality, and structured summary objects for downstream tooling.
2. **Asset Validation**: Checked real PNG magic headers using byte-level buffer comparisons and verified that component image paths (`/images/...`) resolve strictly to disk files to prevent broken image links.
3. **Theme & Tokens Validation**: Extracted CSS custom properties and parsed AST-equivalent regex patterns in `app/globals.css` and `app/layout.tsx` to ensure complete compliance with the obsidian dark theme and design token contracts.
4. **Build & Lint Integration**: Invoked TypeScript compiler (`tsc --noEmit`) and Next.js linter (`next lint`) via isolated child processes to verify zero build or lint regressions.
5. **Cross-Platform Test Runner**: Utilized `pathToFileURL` from `node:url` to support Windows ESM dynamic module imports seamlessly.

## 3. Caveats
- Asset presence tests in `asset_verification.test.ts` will report missing files until the synthetic 3D image assets in `public/images/` are generated by the asset generation workflow (M1).
- Typecheck in `build_and_lint.test.ts` executes `tsc --noEmit` across the whole codebase; any type inconsistencies introduced in newly added test files or components will be caught and reported.

The E2E test infrastructure, core test harness, asset validator, theme token validator, build/lint checker, and master test runner are fully implemented, verified, and operational. All test files execute cleanly and provide comprehensive diagnostics.
